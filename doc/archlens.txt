ArchLens                                        Human-first code relationships

ArchLens is a Neovim side pane for exploring local structure and project-level
relationships around the symbol under the cursor. It uses Tree-sitter,
attached language servers, ast-grep, and ripgrep when they are available. No
LLM or hosted service is required.

COMMANDS                                                   *archlens-commands*

                                                        *:ArchLensHere*
:ArchLensHere          Open or refresh ArchLens for the symbol under the
                       cursor.

                                                        *:ArchLensRefresh*
:ArchLensRefresh       Re-run analysis for the current focus and rebuild
                       cached module relationships. Manual section state is
                       preserved.

                                                        *:ArchLensClose*
:ArchLensClose         Close the ArchLens pane.

ArchLens does not define a global mapping. Map |:ArchLensHere| explicitly if
you want one. For example: >lua

    vim.keymap.set("n", "<leader>cm", "<cmd>ArchLensHere<cr>", {
      desc = "Explore code relationships",
    })
<

PANE MAPPINGS                                              *archlens-mappings*

The following mappings are local to the ArchLens pane:

<CR>            Open a relationship or toggle a section or context group.
f               Focus a relationship and add the previous symbol to history.
F               Toggle source-cursor following. Pinned mode is the default.
<BS>, h         Return to the previous focus.
<Tab>           Move to the next actionable row.
<S-Tab>         Move to the previous actionable row.
]s, [s          Move to the next or previous section.
<Space>, za     Toggle a section or context group.
zM              Collapse every visible section.
zR              Expand every visible section and context group.
?               Inspect the current line, or show the complete pane help.
r               Refresh the current focus.
q               Close ArchLens.

The details window opened by `?` closes with `q`, `<Esc>`, or `?`. ArchLens
keeps one details window open. Opening another details or help view replaces
it. Closing the window returns focus to the ArchLens pane.

`Sources [?]` and `Analysis [?]` mark provider lifecycle details that can be
opened with `?`. `Analysis [?]` appears while providers are active or when a
provider ends with an exceptional outcome. Active provider names remain
visible when they fit. At narrower widths ordinary running and queued work is
summarized by count; failures, timeouts, unavailability, cancellation, and
retries take priority. Completed providers do not leave persistent status
noise.
The details include the time to the first useful relationship.

After the first focused relationship, `Path [?]` shows the previous and
current focus. Its details contain the complete path and available back count.
ArchLens retains up to 32 previous focuses.

Source-cursor following watches only the tracked source window. It debounces
cursor movement, skips repeated movement within one symbol, and does not add
automatic changes to history. Manual focus and back navigation return to
pinned mode.

`Results [?]` compacts relationship filtering, provider caveats, and bounded
analysis into one line. Its details retain each exact message. The persistent
footer shows only primary controls; press `?` on an ordinary line for the
complete pane key reference.

Semantic references covered by incoming-call occurrences are folded into the
caller row and remain inspectable with `?`. Non-call references stay separate.
When semantic calls, references, implementations, or type hierarchy
relationships exist, unmatched structural candidates start collapsed as
secondary evidence. They start expanded when structural analysis is the only
available usage source.

Rows within a section are ordered by evidence quality and filesystem locality.
Exact corroborated relationships appear first, followed by other exact,
provider-defined, and structural evidence. Lower-ranked rows remain available
through section expansion.

Type-like focuses show their Tree-sitter children as members. Language
adapters may project canonical type hierarchy relationships into familiar
roles. For example, Go interfaces distinguish satisfied contracts, extending
interfaces, and concrete implementations. Unsupported semantic type
relationships remain absent.

CONFIGURATION                                         *archlens-configuration*

Call `setup()` without options to use the defaults: >lua

    require("archlens").setup()
<

The plugin loads with defaults automatically. Later `setup()` calls merge
their options into the active configuration.

Built-in configuration tables reject unknown keys. Counts, sizes, and row
limits must be positive integers. Timeouts, delays, minimum name length, and
thread count must be non-negative integers. Commands and list entries must be
non-empty strings. The `providers` table remains open for provider-defined
settings.

                                                    *archlens-config-general*
GENERAL OPTIONS ~

`width` (number, default `56`)
    Width of the ArchLens pane in columns.

`max_items` (number, default `8`)
    Default number of visible rows in each section and expanded context group.

`include_external` (boolean, default `false`)
    Include relationships outside the selected project root.

`providers` (table, default `{}`)
    Provider-specific configuration keyed by provider ID. See
    |archlens-providers|.

                                               *archlens-config-cursor-follow*
CURSOR FOLLOWING ~

`cursor_follow.enabled` (boolean, default `false`)
    Start |:ArchLensHere| in source-cursor-following mode. The `F` pane
    mapping changes the mode for the current pane.

`cursor_follow.debounce_ms` (number, default `150`)
    Delay in milliseconds after the latest source cursor movement.

                                                    *archlens-config-sections*
SECTION POLICY ~

`sections.collapse_secondary` (boolean, default `true`)
    Collapse unmatched structural candidates when semantic usage exists.

`sections.default_collapsed` (list, default `{ "siblings" }`)
    Relationship IDs that start collapsed. Use an empty list to start regular
    sections open.

`sections.hidden` (list, default `{}`)
    Relationship IDs omitted from the model and navigation. ArchLens reports
    the number of hidden relationships.

`sections.max_items` (table, default `{}`)
    Visible-row limits keyed by relationship ID. These values override
    `max_items`.

`sections.order` (list, default `{}`)
    Relationship IDs placed first. Unlisted relationships retain registry
    order.

Built-in relationship IDs are: >

    children              supertypes             subtypes
    implementations       incoming               outgoing
    module_imports        module_importers       configuration_consumers
    test_references       references             test_structural
    structural            siblings
<
Extensions may register additional IDs. See |archlens-providers|.

                                                     *archlens-config-filters*
PROJECT FILTERS ~

`filters.include_generated` (boolean, default `false`)
    Include generated paths and recognized generated files.

`filters.include_vendored` (boolean, default `false`)
    Include vendored and dependency paths.

`filters.exclude` (list, default `{}`)
    Additional project-relative path prefixes to exclude.

                                                     *archlens-config-imports*
MODULE ANALYSIS ~

`imports.enabled` (boolean, default `true`)
    Enable outbound module dependency analysis.

`imports.timeout_ms` (number, default `5000`)
    Time limit for resolving outbound module dependencies.

`imports.max_imports` (number, default `24`)
    Maximum number of distinct visible dependency targets.

`imports.max_sites` (number, default `96`)
    Maximum number of import sites examined in the focused file.

`imports.concurrency` (number, default `4`)
    Maximum number of concurrent definition requests for import sites.

`imports.inbound.enabled` (boolean, default `true`)
    Enable reverse module analysis.

`imports.inbound.command` (string, default `"rg"`)
    ripgrep executable used to enumerate candidate files.

`imports.inbound.timeout_ms` (number, default `8000`)
    Time limit for the reverse module project scan.

`imports.inbound.max_index_files` (number, default `1000`)
    Maximum number of visible candidate files parsed into the in-memory index.

`imports.inbound.max_candidate_files` (number, default `2000`)
    Maximum number of paths accepted from ripgrep before filtering.

`imports.inbound.max_file_bytes` (number, default `1048576`)
    Maximum size of a candidate file parsed for imports.

`imports.inbound.batch_size` (number, default `16`)
    Number of candidate files parsed in each scheduled batch.

`imports.inbound.max_importers` (number, default `24`)
    Maximum number of module dependents returned for the focused file.

                                                         *archlens-config-lsp*
LSP ANALYSIS ~

`lsp.resolve_timeout_ms` (number, default `5000`)
    Time limit for resolving the symbol under the cursor.

`lsp.relationship_timeout_ms` (number, default `8000`)
    Time limit for the semantic relationship requests.

`lsp.max_results` (number, default `256`)
    Maximum number of result items retained from each semantic response.
    ArchLens examines at most four times this number of raw candidates to skip
    malformed and hidden entries and prefer project-local results.

`lsp.max_occurrences` (number, default `256`)
    Maximum number of incoming or outgoing call occurrences retained for a
    semantic request.

`lsp.cold_start_retry.enabled` (boolean, default `true`)
    Retry once when a newly attached server returns no semantic relationships
    and no error. Warm clients complete immediately.

`lsp.cold_start_retry.delay_ms` (number, default `3000`)
    Delay before the cold-start retry.

`lsp.cold_start_retry.window_ms` (number, default `10000`)
    Time after LSP attachment during which an empty response can be retried.

                                                    *archlens-config-grouping*
CONTEXT GROUPING ~

`grouping.enabled` (boolean, default `true`)
    Group test and configuration relationships by their enclosing symbol or
    module.

`grouping.timeout_ms` (number, default `1500`)
    Time limit for resolving context groups.

`grouping.batch_size` (number, default `4`)
    Number of source files examined in each scheduled batch.

`grouping.max_file_bytes` (number, default `1048576`)
    Maximum size of a file parsed for an enclosing context.

`grouping.max_edges` (number, default `500`)
    Maximum number of eligible relationships enriched with an enclosing
    syntax context. Additional relationships remain grouped by file.

                                                    *archlens-config-ast-grep*
STRUCTURAL SEARCH ~

`ast_grep.enabled` (boolean, default `true`)
    Enable project-wide structural candidates.

`ast_grep.command` (string, default `"ast-grep"`)
    ast-grep executable.

`ast_grep.timeout_ms` (number, default `15000`)
    Time limit for a structural search.

`ast_grep.max_results` (number, default `80`)
    Maximum number of decoded structural matches.

`ast_grep.max_output_bytes` (number, default `1048576`)
    Maximum bytes retained from each ast-grep output stream.

`ast_grep.min_name_length` (number, default `5`)
    Minimum symbol-name length required for structural search.

`ast_grep.threads` (number, default `1`)
    Thread count passed to ast-grep.

`ast_grep.globs` (list, default `{}`)
    Additional globs passed to ast-grep. Project filters add their own
    exclusion globs.

The configuration API remains experimental.

HEALTH                                                       *archlens-health*

Run the following from a source buffer: >vim

    :checkhealth archlens
<

The report shows the selected project root, Tree-sitter adapter and parser,
attached language-server capabilities, ast-grep availability, and ripgrep
availability for reverse module analysis. The pane's analysis and result
details report provider-specific runtime failures. Missing optional providers
reduce the available relationships but do not prevent the pane from opening.

LANGUAGE ADAPTERS                                          *archlens-adapters*

Language adapters define Tree-sitter symbols, root markers, module analysis,
relationship presentation, and ast-grep behavior. Register an additional
adapter before opening ArchLens:
>lua

    require("archlens.adapters").register("zig", {
      treesitter = {
        root_markers = { "build.zig", ".git" },
        symbol_types = {
          function_declaration = "Function",
        },
      },
      ast_grep = { language = "zig" },
    })
<

Optional `presentation.section(context, relation, row)` and
`presentation.row(context, relation, row)` hooks adapt relationship labels and
concise row names to language semantics. A section hook may return `key`,
`label`, `order`, or `show_kind`; a row hook may return `name` or `kind_name`.
A presentation key creates an independently collapsible view section while
the underlying relationship ID, direction, evidence, filtering, and details
remain canonical. Presentation hooks should treat their inputs as read-only.

If an adapter callback fails or returns an invalid value, ArchLens reports the
failure in the result details. Presentation falls back to canonical labels and
rows. Module analysis retains unaffected relationships and omits results that
depend on the failed callback.

The focused relationship graph is defined in `lua/archlens/graph.lua`.
Relationship names, directions, and ordering are registered in
`lua/archlens/relations.lua`.

PROVIDER EXTENSIONS                                       *archlens-providers*

Built-in and custom project-analysis providers share one ordered registry.
A provider decides whether it applies, starts its work, calls `done` once with
a graph delta and optional terminal outcome, and returns a cancellation
function. It may use `report` to publish a running or retrying state: >lua

    local graph = require("archlens.graph")

    require("archlens.providers").register("ownership", {
      order = 35,
      label = "Ownership",
      queued = false,
      enabled = function(_, _, config)
        local options = config.providers.ownership or {}
        return options.enabled == true
      end,
      start = function(context, bufnr, config, done, report)
        local result = graph.delta()
        -- Optional: report("retrying", { retry_delay_ms = 1000 })
        -- Add canonical graph edges, then complete the provider.
        done(result)
        return function() end
      end,
    })
<

Provider options belong under `providers.<id>`. Register relationship kinds
through `require("archlens.relations").register()` before returning edges.
The optional `report` callback accepts `"running"` or `"retrying"`; retry
metadata may contain `retry_delay_ms` and a short `message`. ArchLens records
queued, completed, and start-failure states around the provider call.

`done(result)` marks the provider completed. A provider that can classify
another terminal outcome may pass `state` and an optional `message`: >lua

    done(result, {
      state = "timed_out",
      message = "Ownership analysis exceeded 1000 ms.",
    })
<
Terminal states are `completed`, `failed`, `timed_out`, `unavailable`, and
`cancelled`. Partial graph results are retained for every terminal state. Use
`unavailable` only when the provider applies but a required dependency or
capability is unavailable. Disabled or inapplicable providers should not
start.

Every applicable attached LSP contributes location-based relationships.
Provider evidence remains separate when clients return the same row. Opaque
call-hierarchy items remain with the client that resolved the focused symbol.
